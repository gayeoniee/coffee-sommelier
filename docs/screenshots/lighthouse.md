# PWA installability check

## What was tried

```
cd web && npm run build && PORT=3057 npm run start
npx -y lighthouse@12 http://localhost:3057 --only-categories=pwa --quiet \
  --chrome-flags="--headless=new" --output=json --output-path=./lh.json
```

Result: `lighthouseVersion: 12.8.2`, but the report's `categories` object was
**empty** (`{}`) and none of the 176 audits it did run were PWA-related
(no `installable-manifest`, `service-worker`, `maskable-icon`, etc.). Lighthouse
removed the PWA category starting in v10 (it now lives only in a separate
PWA plugin), so `--only-categories=pwa` silently matches nothing on v12. This
confirms the plan's fallback condition: Lighthouse 12 cannot audit PWA
installability, so installability was verified manually instead.

## Manual installability check (what was run and what was seen)

Server: `npm run build && PORT=3057 npm run start` (production build, so
`SwRegister` actually calls `navigator.serviceWorker.register`).

1. **Endpoints** (`curl`, all `200`): `/`, `/manifest.webmanifest`, `/sw.js`,
   `/sw-routes.js`, `/offline`, `/icons/icon-192.png`,
   `/icons/apple-touch-icon.png`, `/screenshots/home.png`.
2. **Manifest content** (`curl /manifest.webmanifest`): `name`, `short_name`,
   `description`, `start_url: "/"`, `display: "standalone"`,
   `background_color`/`theme_color: "#faf6f0"`, `categories: ["food",
   "lifestyle"]`, `icons` with a 192x192 (`purpose: "any"`), a 512x512
   (`purpose: "any"`) and a 512x512 `purpose: "maskable"` entry, and 4
   `screenshots` (`form_factor: "narrow"`) — this is the full set of fields
   Chrome's installability check requires (name + icons ≥192/512 + a
   maskable icon + `start_url` + `display` other than `browser`).
3. **`<head>` tags** (`curl / | grep`): `<link rel="apple-touch-icon"
   href="/icons/apple-touch-icon.png"/>` present, generated by
   `metadata.icons.apple` in `app/layout.tsx`.
4. **Script syntax**: `node --check public/sw.js` and `node --check
   public/sw-routes.js` both OK — confirms both are valid classic
   (non-module) scripts, so `importScripts("/sw-routes.js")` works without a
   bundler.
5. **Real-browser check** (Playwright/Chromium, headless, against the
   `npm run start` server):
   - `link[rel="manifest"]` resolves to `/manifest.webmanifest`; fetching it
     and re-checking the icon/maskable/description conditions above all pass.
   - `navigator.serviceWorker.getRegistrations()` after page load returns one
     registration with `scriptURL: "http://localhost:3057/sw.js"` —
     confirms `SwRegister` successfully registers the service worker in a
     production build.
   - After the SW took control (`navigator.serviceWorker.controller !==
     null`), the browser context was set offline and navigated to a
     never-visited route (`/nonexistent-route-should-fallback`). The page
     rendered the offline fallback text ("인터넷 연결이 끊겨서 이 페이지를
     불러올 수 없어요."), confirming the network-first-then-cache-then-
     `/offline` navigation strategy in `sw.js` works end to end.
   - One unrelated console error was observed (`502 Bad Gateway`), from the
     app's own `/api/*` proxy call with no backend (`uvicorn`) running
     locally — expected in this environment and unrelated to the PWA checks.

## Known local-environment gaps (not fixable here)

- Served over plain HTTP on `localhost`, not HTTPS. Chrome treats `localhost`
  as a secure context for installability purposes, so this does not block
  local verification, but a real Lighthouse HTTPS audit was not exercised.
- Lighthouse 12's PWA category/audits are unavailable entirely (see above);
  this file is the substitute the plan calls for when that's the case.
