# ADR 0016 — 오픈판 v3: 노트 없는 입력용 태그 모델, 단맛 기권, 속성별 보정 신뢰도 (바디는 다시 미탑재)

- 상태: 채택 (2026-09-28)
- 범위: 오픈 라이선스판(`DATA_VARIANT=open`, 공모전 제출본)만. 전체판은 바뀌지 않는다.

## 맥락
공모전은 데이터 레시피로 겨룬다 — 예측기를 LLM으로 바꾸지 않고 **데이터로** 오픈판 품질을 올려야 한다. 모든 후보를
두 가지로 잰다.

- **E1** — 우리 사람 라벨에서 로스터리 단위 그룹 교차검증(한 로스터리는 학습·평가 한쪽에만). 속성은 로스터리 게이지
  ([ADR 0011](0011-roaster-gauges-feature-model.md)), 태그는 오픈 원두 자기 노트에서 나온 태그.
- **E2** — Zenodo Q그레이더 패널([ADR 0014](0014-public-sources-ediya-twosome-kca-zenodo.md), 평가 전용 — 학습에 절대 안 씀).

탑재 규칙: **E1이 나아지고 E2가 나빠지지 않을 때만**. 스크립트 [`scripts/eval_open_tags.py`](../../scripts/eval_open_tags.py) →
[`phase5_open_tags.json`](../../data/eval/open/phase5_open_tags.json), [`scripts/eval_open_v3.py`](../../scripts/eval_open_v3.py) →
[`phase5_open_v3.json`](../../data/eval/open/phase5_open_v3.json), 탑재본은 여전히 `scripts/train_feature_model.py` 하나가
`config/feature_model_open.json`에 쓴다(속성 머리는 바이트 단위로 그대로, 새 블록 `tags`·`abstain`·`calibration`).

## 1. 향미 태그: 노트 없는 입력용 특징 태그 모델 — 탑재
분석 경로는 입력의 노트 단어를 먼저 태그로 되읽는다(`with_text_cues`). 그래서 태그 예측기가 실제로 일하는 것은 손님이
**산지·가공·로스팅만** 적었을 때다. E1·E2 모두 노트를 뺀 입력("이름 | 산지 | 가공 | 로스팅 | 디카페인")으로 쟀다.

- 라벨: 라이선스가 깨끗한 태그 원두 277건 — roasters_kr 121 · shopify(블루보틀) 9 · shopify_gauged 147, 18개 로스터리
  (RoasterDB는 배포 라이선스 제한이라 제외).
- 후보(태그별 로지스틱, 학습 폴드 양성 5건 이상인 태그만, 임계값은 학습 로스터리 안의 그룹 4-fold로 선택):
  `feat` = ADR 0011의 해석 가능한 특징에서 노트·이웃 특징만 뺀 것, `emb` = 노트 없는 텍스트 임베딩, `both` = 둘 다.
- 기준선: 같은 노트 없는 질의 임베딩의 오픈 이웃 투표(lift 게이트, k=10, 대상 로스터리 제외), 참고로 "학습 폴드 최빈 태그 2개".

| 예측기 | E1 태그 F1 / 대분류 F1 (n=277) | E2 태그 F1 / 대분류 F1 (n=110) |
|---|---|---|
| 오픈 이웃 투표 (이전) | 0.064 / 0.239 | 0.089 / 0.279 |
| 최빈 태그 2개 (참고) | 0.175 / 0.436 | 0.118 / 0.413 |
| **`feat` 특징 로지스틱 (탑재)** | **0.196 / 0.604** | **0.185 / 0.554** |
| `emb` 임베딩 로지스틱 | 0.204 / 0.597 | 0.182 / 0.589 |
| `both` | 0.204 / 0.594 | 0.176 / 0.555 |

- 세 후보 모두 규칙(E1 +0.05, E2 안 나빠짐)을 넘는다. `feat`를 고른 이유: 임베딩 후보와 차이가 잡음 안(F1 ±0.01)인데
  순수 파이썬 로지스틱 35개(특징 29개)라 임베딩 없이 저하 모드에서도 돌고, 가중치를 읽을 수 있다(예: 복숭아 ← 약배전
  +1.40·중약배전 +1.08, 강배전 −1.10 / 초콜릿 ← 브라질 +0.98·중강배전 +0.94·블렌드 +0.56, 2,000m 이상 −1.07). 한편 "시트러스
  ← 콜롬비아·물 공정 디카페인"처럼 표본 몇 개짜리 가중치는 로스터리 표기 습관에 가깝다.
- **정직한 해석**: 이득의 큰 몫은 이웃 투표가 노트 없는 입력에서 거의 아무 태그도 내지 못해서다(재현율 0.04 — lift 게이트가
  흔한 태그를 걸러 냄). 상수 "최빈 태그 2개"도 투표를 이긴다. 모델은 그 상수보다 대분류 F1에서 E1 +0.17, E2 +0.14 낫고,
  태그 F1은 0.2 안팎으로 여전히 낮다 — "산지·가공·로스팅만으로는 개별 향미를 맞히기 어렵다"는 한계를 그대로 둔다.
- 연결(`with_feature_model`): 입력에 노트 단어가 **없을 때만** 투표 태그를 대신하고 근거 "향미 모델(산지·가공·로스팅):
  복숭아 0.25, 시트러스 0.17"을 단다. 노트가 있으면 손님 단어가 앞에 오고 노트를 담은 임베딩의 투표가 뒤를 채운다(그
  상황의 기존 E2: 태그 F1 0.307 → 0.309, 대분류 0.542 → 0.539 — 노트가 규칙 매퍼에 안 걸린 몇 샘플에서만 모델이 끼어듦).
- 후속([ADR 0017](0017-open-tag-fill.md)): 노트가 있을 때 뒤를 채우는 투표가 태그 없는 CQI 이웃에 희석돼, 투표가 2개 미만이면
  향미 표기가 있는 이웃만의 투표로 2개까지 채운다.

## 2. 바디: 게이지 + Shopify 바디 + 본문 바디 단서 — 다시 미탑재
게이지 64건에 Shopify 로스터 표기 바디 46건(`A`, 고도 가림, [ADR 0013](0013-open-labels-weak-supervision.md))과 원두 본문의
명시적 바디 단서 10건(`K`: "묵직한 바디감"·"syrupy" 등 — 국내 5건은 `korean_cue` 라벨)을 학습 쪽에만 더했다.

| 후보 (릿지 + 이웃 특징) | E1 ±1 / MAE / Spearman (n=64) | E2 ±1 / MAE (같은 표본 160, 이웃 평균 0.788 / 0.651) |
|---|---|---|
| 오픈 이웃 평균 (현행) | 0.766 / 0.753 / 0.04 | — |
| 게이지만 | 0.797 / 0.699 / 0.21 | 0.606 / 0.872 |
| + A | 0.750 / 0.712 / 0.24 | 0.744 / 0.727 |
| + A (가중치 1) | 0.766 / 0.707 / 0.27 | 0.800 / 0.676 |
| + K | 0.797 / 0.697 / 0.43 | 0.600 / 0.900 |
| + A + K | 0.781 / 0.659 / 0.39 | 0.719 / 0.727 |

최고 E1 이득이 +0.031(기준 +0.05 미달)이고, E2에서는 모든 후보가 이웃 평균보다 MAE가 나쁘다(패널 바디는 2.5~3.5에 몰려
상수 3이 MAE 0.36). **바디는 이웃 평균을 유지**한다. K는 순위(Spearman 0.21→0.43)는 올리지만 라벨이 10건뿐이다.

## 3. 단맛 기권 — 탑재
E2에서 오픈판 단맛은 순위가 뒤집혀 있고(Spearman −0.23) 상수 3이 모든 예측기를 이긴다. 단맛 모델이 "근거가 약한데도
숫자를 내는" 경우를 줄이려고, 앱이 런타임에 볼 수 있는 근거 신호를 E1 교차검증 잔차에 대 보고 규칙을 **E1에서만** 골랐다.

| 규칙 (답하는 경우) | E1 답한 비율 · ±1 · MAE (n=72) | E2 답한 비율 · ±1 · MAE (n=196) |
|---|---|---|
| 항상 답함 (이전) | 1.00 · 0.569 · 1.050 | 1.00 · 0.418 · 1.375 |
| **문구 단서 또는 이웃 값(10개 중 3개 이상이 단맛 라벨) (탑재)** | **0.51 · 0.595 · 0.968** | **0.89 · 0.443 · 1.323** |
| 문구 단서 또는 노트 단어 | 0.24 · 0.529 · 0.933 | 0.97 · 0.408 · 1.385 |
| 문구 단서 또는 \|모델 − 이웃\| ≤ 1 | 0.46 · 0.606 · 0.980 | 0.78 · 0.412 · 1.371 |
| (탐색, 결과 파일 밖) 로스팅 표기 없을 때만 / 로스터리 간 잭나이프 퍼짐 ≤ 0.5 | 0.35 · 0.86 · — (비율 미달) / 0.50 · 0.472 · 1.287 (더 나쁨) | — |

- 탑재 규칙: 답한 경우의 정확도가 두 평가 모두 좋아지고 E1 답한 비율 ≥ 50%. "문구 단서 또는 이웃 값"만 통과한다
  (±1 +0.026/+0.024, MAE −0.08/−0.05). 근거가 없으면 단맛은 `None`, 근거 줄 **"단맛: 근거 부족"**, 카드는 "?"로 보인다
  (점수·템플릿·설명 LLM 입력은 이미 null 속성을 다룬다). 손님 문구에 단맛 단서가 있으면 그 값이 답한다.
- **한계를 숨기지 않는다**: 이득은 작고(E1 72건 중 답한 37건), 답한 경우의 순위는 여전히 틀렸다(Spearman E1 −0.29, E2 −0.26).
  기권은 "근거 없는 숫자를 덜 보여 준다"는 정직성 조치이지 단맛 예측을 고친 것이 아니다. E2에서 기권이 적은(89% 답함) 것은
  패널 샘플 대부분이 단맛 라벨이 있는 이웃을 갖기 때문이다.
- 산미: 같은 규칙들이 E1을 개선하지 못해(0.695 → 0.691~0.720, 답한 비율 0.30~0.99) 기권하지 않는다.
- 프랜차이즈 브랜드 원두 값(ADR 0012 오픈판)은 `FeatureModel.predict`를 직접 쓰므로 기권이 적용되지 않는다 — 공식 문구가
  먼저이고, 브랜드 원두는 이웃이 없어 이 규칙의 근거 정의가 맞지 않는다.

## 4. 속성별 보정 신뢰도 — 탑재
예전 신뢰도는 이웃 값의 표준편차(분산 작으면 "높음")였다 — 오픈판에서는 이웃 평균을 특징 모델이 대신하므로 표시 값과
무관했다. 이제 속성마다, 그 값의 **근거 구간**(`cue` 문구 단서 · `notes` 노트 단어 · `facts` 산지/로스팅만 · `sparse`)별
E1 교차검증 잔차로 정한다: **높음** = ±1 ≥ 0.75 이고 Spearman ≥ 0.3, **보통** = ±1 ≥ 0.55 이고 Spearman > 0, 그 밖은 **낮음**.
표본 10건 미만 구간은 속성 전체 값, `cue`는 손님 자신의 진술이라 늘 높음.

| 속성 | E1 (답한 경우) ±1 / Spearman | 구간별 | 보정 등급 | E2 확인 (±1 / Spearman) |
|---|---|---|---|---|
| 산미 | 0.695 / 0.55 (n=82) | 노트 0.70 · 산지만 0.68 · 없음 0.69 | 보통 | 0.816 / 0.62 |
| 바디 (이웃 평균) | 0.724 / 0.22 (n=29) | 산지만 0.63 | 보통 | 0.788 / −0.03 |
| 단맛 (답한 경우) | 0.595 / −0.29 (n=37) | 산지만 0.41 | 낮음 | 0.443 / −0.26 |

카드(`attr_confidence`)는 속성별 등급을 싣고, 카드 전체 신뢰도(배지 "신뢰도 …")는 보이는 속성 중 가장 낮은 등급이다(속성이
비면 [결측 상한](../../app/models.py) — 하나 비면 최대 보통, 둘 이상이면 낮음). 웹 `TasteBars`는 속성 옆에 등급을, 기권한 속성에
"?"(title "근거 부족")와 "근거↓"를 보인다. 결과적으로 오픈판 예측 카드는 단맛을 답하면 "낮음", 기권하면 "보통"이 된다 — 가장
약한 값이 카드의 신뢰도를 정한다는 규칙 그대로다.

## 같은 날 함께 고친 것 (운영 점검에서 나온 버그)
- "에티오피아 … 라이트 로스트"가 산미 2.94를 보이면서 근거는 "유사 원두 산미 평균 4.1/5"와 "→ 산미↑"였다. 2.94는 특징
  모델 값이었다(기준값 2.2가 게이지 척도라 이웃 평균보다 낮고, ↑는 그 기준값 대비). 이제 모델 줄이 값과 기준값을 함께 말하고
  ("특징 모델 산미 2.9/5: 약배전·에티오피아 ↑ (기준값 2.2)"), 값을 바꾼 층은 이전 값을 말하던 줄을 지운다.
- "라이트 로스트"를 가벼운 바디 단서로 읽던 것, 쉼표 없는 한 줄 입력의 한국어 노트(딸기·재스민·자스민)를 못 읽던 것을 고쳤다.

## 한계
- E1 단맛 대상은 로스터리 3곳 72건, 바디는 3곳 64건 — 한 폴드가 한 로스터리이고 척도 관행 차이가 오차의 큰 몫이다.
- 태그 E1 라벨은 로스터리가 쓴 노트 단어의 규칙 매핑이라 "로스터가 적은 단어"를 맞히는 과제다(맛 자체가 아님). E2는 110개
  샘플만 노트 아닌 입력이 남는다(나머지 82개는 이름·로스팅 표기 없이 노트뿐).
- 기권 규칙·신뢰도 문턱은 이 실험 중에 정했다. 여러 규칙 중 최고를 같은 E1로 고른 선택은 낙관적이고, 그래서 E2 확인을 따로 둔다.
