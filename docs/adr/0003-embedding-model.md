# ADR 0003 — 임베딩 모델: bge-m3(로컬) → nemotron-3-embed-1b(NVIDIA 호스팅)

- 상태: 채택 (2026-09-26)

## 맥락
원두 9,155개의 임베딩은 로컬 Ollama `bge-m3`(1024차원)로 만들었고, 앱은 처음 보는 원두 텍스트를 실행 중에 같은 모델로 임베딩해
유사 원두를 찾는다(`app/graphs/analyze_bean.py` → `Deps.embed`). 배포 대상(Render 무료, RAM 512MB)에서는 Ollama를 돌릴 수 없고,
NVIDIA API 카탈로그의 호스팅 `baai/bge-m3`는 지원 종료(HTTP 410)됐다. 저장된 벡터와 실행 중 질의 벡터는 **같은 모델**이어야 하므로
호스팅 모델로 바꾸려면 전체 코퍼스를 다시 임베딩해야 한다.

## 대안
| 대안 | 장점 | 단점 |
|---|---|---|
| bge-m3 유지 + 서버에 Ollama | 재임베딩 없음 | 512MB RAM에 모델(1.2GB)이 안 올라감 |
| 호스팅 `baai/bge-m3` | 재임베딩 없음 | 410 Gone (지원 종료) |
| **`nvidia/nemotron-3-embed-1b`** | 같은 API 키, 다국어, 비대칭(passage/query), Matryoshka 학습 | 2048차원 → 스키마(vector(1024))와 맞춰야 함 |

차원: API의 `dimensions` 파라미터는 거부된다(`"dimensions must be one of 2048"`). 모델 카드에 따르면 Matryoshka(MRL, 투영층 없이 앞부분을
잘라 학습)로 384~2048 어느 크기로 잘라 써도 된다. 그래서 **앞 1024개만 쓰고 단위 길이로 재정규화**한다(`pipeline/llm.py::truncate_normalize`).
DB 스키마 `vector(1024)`와 HNSW 인덱스(최대 2000차원)는 그대로다. halfvec(2048)은 필요 없었다.

## 결정
- 기본 `embed` 태스크 = `nvidia/nemotron-3-embed-1b`, `dims: 1024`, `asymmetric: true`, 요청당 32개, 분당 35요청 제한.
  원두(저장 문서)는 `input_type: "passage"`, 앱·`pipeline query`의 실행 중 텍스트는 `"query"`.
- bge-m3는 `embed_bge_m3` 태스크로 남긴다(`EMBED_TASK=embed_bge_m3`). 임베딩 캐시는 모델별 폴더(`data/embedded/<모델>/`)라
  전환해도 서로 덮어쓰지 않고, 해당 모델 캐시가 없으면 `load`가 임베딩을 비우는 대신 중단한다.
- 임베딩 문장(`pipeline/embed.py::embedding_text`)은 바꾸지 않았다 — 9,155건 모두 텍스트 해시가 bge-m3 때와 같다.
- 429/5xx/타임아웃은 지수 백오프(Retry-After 우선)로 최대 5번 재시도.

## 실측
재임베딩: 9,155건, 287요청, 약 12분 30초, 재시도 실패 0건. DB `coffee`의 활성 원두 9,155개 모두 임베딩 있음.

LOO(원두 하나를 빼고 이웃 10개로 산미·바디·단맛 예측, ±1 이내 비율). 대상 원두는 두 모델에서 같다(`target_ids_sha1` 동일).
bge-m3 값은 현재 DB로 다시 돌려 커밋된 값과 같음을 확인했다(`data/eval/phase2_*_bge-m3.json`).

| 평가 | 항목 | bge-m3 | nemotron (1024) | 차이 |
|---|---|---|---|---|
| `loo` (전체 소스) | 산미 ±1 | 0.75 (n=200) | 0.735 (n=200) | −1.5%p |
| | 바디 ±1 | 0.65 | 0.635 | −1.5%p |
| | 단맛 ±1 | 0.8878 (n=98) | 0.875 (n=96) | −1.3%p |
| `loo_open` (오픈 라이선스) | 산미 ±1 | 0.5204 (n=196) | 0.5202 (n=198) | 0 |
| | 바디 ±1 | 0.551 (n=196) | 0.5808 (n=198) | +3.0%p |
| `compare3` 전체 (CQI 고정 200개) | 산미 / 바디 ±1 | 0.49 / 0.525 | 0.505 / 0.575 | +1.5 / +5.0%p |
| `compare3` 오픈 | 산미 / 바디 ±1 | 0.495 / 0.54 | 0.49 / 0.565 | −0.5 / +2.5%p |
| `compare3` 오픈 + 로스터리 | 산미 / 바디 ±1 | 0.4975 / 0.5377 (n=199) | 0.49 / 0.565 (n=200) | −0.75 / +2.7%p |

커버리지·디카페인 페르소나 top5는 임베딩과 무관해 그대로다. compare3에서 CQI 대상의 이웃은 nemotron에서 100% CQI(bge-m3는 97~99.6%)라
세 판의 LOO가 같아졌다 — 오픈·오픈+로스터리 차이가 0이 된 것은 모델 차이가 아니라 이웃 풀이 CQI로만 채워진 결과다.

한국어 질의 → 영어·한국어 원두 검색 top5(`data/eval/embedding_sanity_ko.json`) 요약:
- "산미 있는 에티오피아 디카페인": 두 모델 모두 1~4위가 같은 에티오피아 디카페인(국내 1킬로커피·커피 리브레 포함). 5위는 bge-m3가 일반(카페인) 원두, nemotron이 디카페인.
- "고소하고 초콜릿 같은 브라질 원두": bge-m3는 노트 없는 브라질 블렌드 5개(이름만 비슷), nemotron은 5개 모두 초콜릿·견과 노트가 있는 브라질 원두.
- "딸기 같은 내추럴 가공": nemotron top5 모두 내추럴, 4개가 strawberry 태그. bge-m3는 top5에 wet-hulled 원두 1개가 섞임.
- "꽃향 나는 게이샤 워시드": 둘 다 게이샤/게샤 5개. nemotron 5위에 내추럴 1개.
- nemotron의 질의-문서 유사도 절대값은 bge-m3보다 낮다(top5 기준 0.28~0.60 vs 0.47~0.67). 순위만 쓰고 임계값은 쓰지 않으므로 영향 없음.

## 결과
- LOO 차이는 README에 적어 둔 동점 잡음(±1~3%p) 안이고, 오픈 라이선스판 바디는 오히려 나아졌다. 명확히 나빠진 지표가 없어 기본값으로 채택했다.
- 개발과 프로덕션이 같은 모델·같은 벡터를 쓴다. 대신 실행 중 임베딩이 NVIDIA API에 의존하므로, 실패하면 기존 폴백(산지·가공 평균, 신뢰도 낮음)으로 떨어진다.
- 모델을 바꾸려면 `EMBED_TASK=<태스크> uv run python -m pipeline run --only embed --only load` 후 평가를 다시 돌린다.
- 무료 API 한도(분당 요청 수)는 코드에서 35rpm으로 묶었다. 전체 재임베딩 1회 ≈ 290요청.
