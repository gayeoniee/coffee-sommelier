# ADR 0017 — 오픈판 향미 태그 채우기: 향미 표기가 있는 이웃만의 투표로 얇은 투표를 2개까지, 한국어 노트 별칭

- 상태: 채택 (2026-09-29) — 후속: [ADR 0018](0018-open-tag-cooccurrence.md)(손님 단어 하나만 남을 때 공기 채우기, 정밀도 회복
  후보 기각, 별칭 인식률의 보지 않은 로스터리 수치 +4.9%p)
- 범위: 오픈 라이선스판(`DATA_VARIANT=open`, 공모전 제출본)만. 전체판은 학습형 태그 모델([ADR 0008](0008-learned-tag-model.md))이
  투표를 대신하므로 바뀌지 않는다(한국어 별칭은 두 판 공통의 규칙 매퍼에 들어간다).

## 맥락
운영에서 한국어 원두 문구 10개를 분석하면 오픈판은 원두당 향미 태그 1.7개(8/10 원두), 전체판은 3.8개(10/10)였다. 가설:
`coffee_open` 원두 2,063개 중 1,546개가 **향미 태그가 없는 CQI 행**이라, 임베딩 이웃 10개가 대부분 태그가 없고 투표(10개 중
30% 이상 + lift 게이트, [ADR 0007](0007-tag-lift-gate.md))가 좀처럼 통과하지 못한다. 손님이 노트 단어를 하나라도 적으면 노트 없는
태그 모델([ADR 0016](0016-open-variant-v3.md))은 물러나고 손님 단어 뒤를 이 희석된 투표만 채운다 — 가장 약한 경우다.

제약: 오픈판은 coffeereview 파생 라벨을 학습·표시에 쓰지 않는다, Zenodo는 평가 전용(CC BY-NC), RoasterDB(CC BY-NC)는 새 예측에
쓰지 않는다, LLM이 태그를 짐작하게 하지 않는다, 손님이 직접 쓴 단어가 항상 먼저다.

## 평가 설계 — [`scripts/eval_open_tag_fill.py`](../../scripts/eval_open_tag_fill.py) → [`phase6_open_tag_fill.json`](../../data/eval/open/phase6_open_tag_fill.json)
ADR 0016과 같은 누수 없는 입력(원두 자신의 저장 임베딩이 아니라 질의 텍스트를 새로 임베딩)으로 두 상황을 잰다.

- **노트 없는 입력**: "이름 산지 가공 로스팅 디카페인". 정답 = 원두의 태그. 현재 경로 = 노트 없는 특징 태그 모델, 안 나오면 투표.
- **노트 한 단어 입력**: 같은 카드 + 원두의 **첫 노트 단어**. 그 단어는 손님 단어로 먼저 보이고(에코), 예측기의 몫은 나머지다.
  정답 = 원두 태그 − 에코, 채점은 **채운 태그만**(에코를 채점하면 순환). 현재 경로 = 에코 + 투표.
- **E1**: 라이선스가 깨끗한 태그 원두 277건(roasters_kr·shopify·shopify_gauged, 18개 로스터리) 로스터리 단위 교차검증 — 이웃
  풀에서 대상 로스터리를 늘 뺀다. 노트 한 단어 입력은 첫 노트가 규칙 매퍼에 걸리고 남는 정답이 있는 137건.
- **E2**: Zenodo Q그레이더 패널(평가 전용) — 노트 없는 카드 110건(ADR 0016과 같음), 첫 패널 노트 단어를 붙인 카드 53건.
- 지표: 마이크로 정밀도·재현율·F1, SCA 대분류 F1, 원두당 보이는 태그 수(에코 포함, 최대 5), 태그 1개 이상 보이는 원두 비율.
- 탑재 규칙(이 작업의 요구): 태그를 늘리는 변경은 현재 정밀도보다 **0.05 넘게** 떨어지면 안 되고, E1·E2 모두 F1·대분류 F1이
  나빠지지 않아야 한다.

## 결정
1. **탑재 — 태그 채우기** (`app/core/predict.py` `with_tag_fill`, `app/graphs/analyze_bean.py`): 오픈판에서 이웃 투표가 태그를
   **2개 미만**으로 내면, 같은 질의 임베딩의 k=10 최근접 중 **향미 태그가 있는 원두만**(RoasterDB 제외, `Repo.neighbors(...,
   tagged_only=True, exclude_sources=("roasterdb",))`) 모은 투표로 2개까지 채운다. 투표 자신의 태그는 지우거나 순서를 바꾸지 않고,
   근거 줄 "유사 원두(향미 표기 있는 것) 10개 중 4개에서 '라임' 언급"을 단다. 우선순위는 그대로 — 손님 단어 > 노트 없는 태그 모델
   (노트가 없을 때 채운 투표까지 대신함) > (채운) 투표. 임베딩이 실패한 저하 모드와 전체판에서는 돌지 않는다(`TAG_FILL=off`로 끔).
   - 노트 한 단어 입력: E1 대분류 F1 0.315 → **0.507**, F1 0.106 → 0.126, 태그 1.84 → 2.51개. E2 대분류 0.316 → 0.364, F1 0.142 →
     0.151, 태그 1.87 → 2.13개. 정밀도는 E1 −0.039, E2 −0.048 — 허용 폭(0.05) 안이지만 E2는 경계에 가깝다.
   - 기존 외부 점검(노트 전체가 들어간 Zenodo 카드 192건, [`phase2_zenodo_external.json`](../../data/eval/phase2_zenodo_external.json)
     오픈판, 에코 전 태그)도 같은 방향: 정밀도 0.371 → 0.359, F1 0.309 → 0.311, 대분류 0.539 → 0.564.
   - RoasterDB를 뺀 풀을 고른 이유: 포함 풀이 정밀도는 조금 낫지만(E1 −0.034, E2 −0.027) 새로 보이는 태그가 비영리 조건의
     라벨에서 나오면 안 된다는 제약을 따랐다. 대분류 F1은 뺀 풀이 오히려 높다(0.507 vs 0.455).
2. **탑재 — 한국어 노트 별칭** (`pipeline/enrich.py` `KO_TAG_ALIASES`): 국내 로스터리·블루보틀 코리아 노트에서 가장 자주 못 읽던
   단어와 손님이 흔히 쓰는 단어를 가장 가까운 SCA 휠 노드로(밀크초콜릿·초콜렛 → 초콜릿, 견과류·고소한·캐슈넛 → 견과, 갈색설탕 →
   흑설탕, 청포도 → 포도, 살구·핵과류 → 복숭아, 감귤류 → 시트러스, 만다린 → 오렌지, 휠에 없는 과일(자두·망고·리치·패션프룻) →
   기타 과일, 히비스커스·라일락 → 꽃향 등 49개). 로스터리 노트 항목(한글 429개) 중 태그로 읽히는 비율 **57.3% → 74.8%**(별칭을 고른
   노트 안 수치 — 로스터리를 반으로 나눠 한쪽에서 고른 별칭만 다른 쪽에서 재면 61.7% → 66.5%, +4.9%p, [ADR 0018](0018-open-tag-cooccurrence.md);
   "리치한 바디"가 과일 리치로 읽히던 오탐도 ADR 0018에서 막음). 남은
   것은 대부분 질감·평가 단어("쥬시", "섬세하다", "묵직한")와 산문이다. 이 별칭은 파이프라인의 규칙 매퍼와 같은 사전이라, 저장된
   원두 라벨은 다음 적재(enrich) 때부터 바뀐다 — 이 ADR의 E1 정답은 현재 저장 라벨 그대로다.
3. **특징 태그 모델·임계값·설정 파일은 그대로** — `config/feature_model_open.json`은 바뀌지 않는다(새 동작은 코드의 상수
   `FILL_MIN_TAGS = 2`, `FILL_EXCLUDE_SOURCES`와 DB 질의뿐이라 새 학습 산출물이 없다).

## 기각한 것과 이유
- **태그 있는 이웃 투표로 교체**(채우기 대신 항상): E1 F1은 가장 높지만(0.129) E2 정밀도 −0.055로 허용 폭을 넘는다.
- **노트가 있어도 특징 모델 또는 "특징 모델 + 투표"**: 대분류 F1은 가장 높지만(0.61~0.62) E2 정밀도가 0.341 → 0.13~0.17로
  무너진다 — 손님이 노트를 적은 원두에 산지·로스팅만으로 짐작한 태그 4개를 덧붙이는 것은 정밀도 규칙에 걸린다.
- **노트 없는 입력에 투표 덧붙이기**(특징 모델 + 태그 있는 이웃 투표): F1 +0.00~+0.02, 대분류 ±0.01 — 잡음 폭이고 ADR 0016의
  탑재 기준(+0.05)에 못 미친다. 태그 수만 3.6 → 4.1로 늘어 기각. 이 입력은 이미 태그 있는 원두 99.6%다.
- **(b) 오픈 라벨로 학습한 태그 모델**: 임베딩 로지스틱은 ADR 0016의 `emb`와 같고(노트 없는 입력 F1 0.204, 특징 모델과 잡음 차이),
  MLP(은닉 64)는 277건에 과적합해 E1 0.159 · E2 0.083으로 더 나쁘다. 노트 한 단어 입력에서는 둘 다 E2 정밀도가 0.13·0.20으로 떨어진다.
- **(d) 태그별 임계값**: 태그를 늘 5개 채우며 정밀도가 0.14/0.15(노트 없는 입력)로 떨어진다(−0.02 / −0.12). **게이트 강화**(40%,
  lift 2.0)는 정밀도를 올리지만 태그 수가 현재보다 줄어 목적과 반대다. **k=5/20**은 k=10보다 F1이 낮다.

로컬에서 A 묶음의 이전 값(2.7개, 10/10)이 운영에서 잰 1.7개(8/10)보다 이미 높다 — 운영 배포본이 ADR 0016의 태그 모델을 아직
싣지 않았거나 운영 DB가 다를 수 있다(이 작업에서 운영은 건드리지 않았다).

## 한계
- 별칭 단어와 B 묶음은 같은 사람이 같은 날 골랐다 — B 묶음의 인식 개선은 낙관적이다. 로스터리 노트 인식률(57% → 75%)도 그 노트에서
  고른 단어라 표본 안 수치다(보지 않은 로스터리에서는 +4.9%p, ADR 0018). "자두·망고 → 기타 과일"처럼 휠에 없는 과일은 칩이 "기타 과일"로 보인다(대분류는 맞다).
- "노트 한 단어 입력"은 첫 노트 단어를 손님 입력으로 가정한 모의 상황이다. E2는 53건뿐이라 정밀도 차이 0.05는 채운 태그 몇 개다.
- 여러 후보 중 최고를 같은 E1·E2로 고른 선택은 낙관적이다. 채우기 개수 2는 작은 격자(1·2·3개 상한, 교체)에서 골랐다.
- 기존 투표(전체 이웃)는 RoasterDB 태그도 읽는다 — 이번 변경은 새 채우기 풀만 RoasterDB를 뺐다. 기존 투표 풀까지 바꾸는 것은
  이 ADR 범위 밖이다.
