# ADR 0014 — 공개 출처 추가: 이디야 음료 페이지, 투썸 원두 게이지, 소비자원 차 음료 시험, Zenodo 외부 검증

- 상태: 채택 (2026-09-28)
- 범위: 전체판·오픈판 공통(데이터 출처). Zenodo 패널 데이터는 평가 전용.

## 맥락

메뉴를 음료 단위로 실측한 브랜드는 7곳이었고, 이디야는 "메뉴 데이터가 robots.txt 차단 경로(`/inc/`)로만 제공"된다고 보고
원두 카드만 냈다. 투썸은 "봇 차단"으로 원두 값 4개(산미·바디 × 하우스·디카페인)가 손 추정이었다. 공모전 제출본(오픈판)에
넣을 수 있는, 라이선스가 분명한 공개 사실을 더 찾았다.

## 결정

### 1. 이디야 공식 음료 페이지 (`EdiyaCollector`, `normalize_ediya`)

- `https://ediya.com/contents/drink.html`은 서버가 HTML로 카드를 그린다. 카테고리 체크(`chked_val`)와 검색어(`skeyword`)를
  함께 받아 **첫 8개 카드**만 그리고, "더보기"는 `/inc/ajax_brand.php`(robots.txt `Disallow: /inc/`)라 부르지 않는다.
  robots.txt가 막는 경로는 `/admin/ /manager/ /member/ /inc/ /checkplus/`뿐이라 이 페이지 자체는 허용이다.
- 그래서 카테고리 2개(12=COFFEE, 155=DECAF) × (검색어 없음 + 고정 검색어 22개)를 `PoliteClient`로 조회한다(46요청).
  검색은 메뉴 이름의 띄어쓰기를 그대로 맞춰야 해서("카페라떼" 0건, "카페 라떼" 8건) 검색어는 사이트 표기를 따른다.
  돌체·토피넛 라떼는 현재 메뉴에 없다.
- 카드마다 이름, `(L)`/`(EX)` 사이즈, HOT/ICED, 카페인 mg, 컵용량(ml)이 있다. 음료 하나 = 항목 하나로 합치고 **L(기본) 컵의
  카페인**, HOT/ICED 중 큰 값을 쓴다(컴포즈·할리스와 같은 규칙). 컵용량은 사이즈 판정에만 쓰고 저장 컬럼은 없다.
- DECAF 카테고리는 같은 이름 음료의 디카페인 SKU(카페인 3~50mg)다 → `디카페인 <이름>` 별도 항목. 이 탭의 차 음료
  (아샷추 복숭아 = "Peach Iced Tea with Espresso")는 커피 음료가 아니라 뺀다.
- "얼박샷추(디카페인 원두)"는 디카페인 원두지만 에너지 음료 때문에 163mg이다 → 앱의 저카페인 선(100mg)을 넘는 "디카페인"
  카드는 디카페인으로 보지 않고, 그 원래 음료(얼박샷추)도 "디카페인으로 변경" 대상에서 뺀다.
- DECAF 카테고리가 대표 커피 음료 대부분의 디카페인판을 싣는 것이 공식 근거라 `brands.yaml` 이디야
  `decaf_option_categories`를 `[COFFEE]`로 바꿨다(콜드브루처럼 샷이 없는 음료는 기존 `NO_SHOT_WORDS` 규칙으로 제외).
- 결과(2026-09-28): 41개 항목(COFFEE 22 · DECAF 19), 카페인 41/41, 디카페인 19. 우유 라벨 26건을 손으로 추가했다
  (`data/curated/menu_milk_labels.yaml`, 음료 설명·알레르기 표기로 판단).

### 2. 투썸 원두 게이지 (`data/curated/brand_beans_official.yaml`)

- `https://www.twosome.co.kr/mn/coffeeStory.do`에 블렌드 3종의 로스팅·산지·한국어 설명·영어 설명어와 **산미·바디 막대(%)**가
  있다. robots.txt에는 Disallow가 없지만 CloudFront가 봇 UA(`PoliteClient` 포함)를 403으로 막는다. 우회하는 수집기는 만들지
  않고, 공개 페이지를 브라우저로 한 번 열어 **사실만 손으로 옮겼다**(URL·확인일 기록).
- 막대는 `gauges_pct`로 적고 `scripts/derive_brand_beans.py`가 `1 + 4·p/100`(소수 한 자리)로 1~5에 옮긴다 → `official_gauge`.
  게이지는 라이선스 제약이 없는 브랜드 공식 사실이라 전체판·오픈판 모두 같은 값을 쓴다. 게이지가 없는 단맛·향미는
  [ADR 0012](0012-official-brand-beans.md)의 기존 규칙(전체판 문구>모델, 오픈판 문구>특징 모델)을 따른다.

| 원두 | 산미 | 바디 | 단맛 (전체/오픈) | 향미 |
|---|---|---|---|---|
| 블랙그라운드(하우스) | 2 → **2.6** (40%) | 4 → **5.0** (100%) | 2 → 2.5 / 5 | chocolate, smoky, nutty |
| 디카페인 | 2 → **2.6** (40%) | 3 → **4.2** (80%) | 3 → 4 / 4 | nutty |
| 아로마노트(선택 원두, 값에는 안 씀) | (80% = 4.2) | (60% = 3.4) | — | berry, floral |

### 3. 한국소비자원 프랜차이즈 카페 차음료 품질비교 (`data/curated/kca_tea_drinks_2026.yaml`)

- 비교공감 제2026-8호(2026-05-28): 매장 수 상위 6개 브랜드(메가·빽다방·스타벅스·이디야·컴포즈·투썸)의 말차/녹차라떼 6개와
  밀크티 6개를 한국소비자원이 **직접 시험**한 1잔 기준 카페인·당류·포화지방·열량·용량·가격. 종합결과표(붙임 4)를 손으로
  옮겼다. 카페인 45~172mg, 밀크티 2개(스타벅스 172mg · 투썸 148mg)는 아메리카노 1잔보다 많다.
- 라이선스: KCA 보도자료 게시판 표기는 "공공누리 제0유형(자유이용)", 같은 발표의 정책브리핑 게시물은 제1유형(출처표시).
  더 엄격한 **제1유형 조건(출처표시)**을 따르고 출처표시 문구를 파일에 함께 둔다.
- 쓰임: ① `apply_kca_caffeine`(정규화 단계) — 같은 브랜드의 같은 음료 이름이 메뉴에 있고 카페인이 비어 있을 때만 채운다.
  현재 메뉴 수집은 커피 카테고리 위주라 겹치는 항목은 메가 2개뿐이고 둘 다 브랜드 값이 있어 **채운 값은 0건**이다.
  대신 교차검증 쌍이 생겼다: 메가 녹차라떼 브랜드 표기 72.5mg vs 소비자원 실측 45mg, 로얄밀크티라떼 118.1mg vs 57mg —
  브랜드 표기(최대치 기준으로 보임)가 실측보다 높다. ② 공모전 초안 문제 정의("커피가 아니어도 카페인") 근거.

### 4. Zenodo Q그레이더 패널 — 외부 검증 전용 (`scripts/eval_zenodo_panel.py`)

- "Electrochemical profiles of coffee drink samples" v1.1 ([doi:10.5281/zenodo.20840464](https://doi.org/10.5281/zenodo.20840464)),
  `panelists_scores_EN.xlsx`: 196개 샘플 × Q그레이더 1~4명(526행), 산미·단맛 **강도** 5단계와 바디 서술, 향 서술.
  러시아 로스터리 원두(디카페인 2개)라 우리 카탈로그와 겹치지 않는 **독립** 평가셋이다.
- 라이선스: 레코드 메타데이터는 CC BY 4.0, 본문 설명은 CC BY-NC 4.0 — 더 엄격한 **CC BY-NC 4.0**으로 다룬다. 파일은
  `data/raw/`(git 제외)에 내려받아(md5 확인) 평가에만 쓰고, 학습·DB 적재·재배포는 하지 않는다. 결과 파일에는 집계 지표와
  출처표시만 남긴다.
- 진실값: 산미·단맛 = 패널 강도 평균(low 1 … high 5). 바디 = 서술의 무게 단어 사전(watery 1 · light 2 · medium/average 3 ·
  dense/enveloping 4 · syrupy/thick 4.5 · heavy 5, "below/above average" 2/4, 질감 단어는 무시).
- 입력: 손님이 붙여 넣는 원두 카드처럼 — 로스터리+산지(러시아어 국가명 번역 사전)+로스팅(시트의 용도 표기를 가정 매핑:
  필터 → light, 에스프레소 → medium, 우유용 → dark)+향 노트(aroma·bouquet). 강도가 적힌 산미·단맛·바디 서술은 넣지 않는다.
- 예측: 분석 화면 `predict` 노드와 같은 함수 순서(규칙 파싱만, LLM 파싱 없음). 향미 태그는 텍스트 단서 **이전** 태그로
  채점한다(최종 태그는 입력 노트를 그대로 되읽어 순환).

| 속성 (n) | 전체판 MAE · ±1 · Spearman | 오픈판 MAE · ±1 · Spearman | 상수 3 MAE · ±1 |
|---|---|---|---|
| 산미 (196) | 0.57 · 83.7% · **0.70** | 0.64 · 80.1% · **0.61** | 0.93 · 65.3% |
| 단맛 (196) | 1.18 · 41.8% · 0.63 | 1.58 · 34.7% · **−0.23** | 0.65 · 77.0% |
| 바디 (전체 195 / 오픈 160) | 0.52 · 88.7% · 0.18 | 0.65 · 78.8% · −0.03 | 0.36 · 98.5% |
| 향미 태그 F1 / 대분류 F1 (192) | 0.44 / 0.68 | 0.31 / 0.54 | — |

- **산미는 외부 패널에서도 순위가 맞는다**(Spearman 0.70/0.61, 상수 기준선보다 MAE 0.3 낮음). 두 판 모두 이 결론은 같다.
- **단맛은 척도가 다르다.** 전체판은 순위는 맞지만(0.63) 평균이 3.67로 패널(2.51)보다 1 이상 높다 — 우리 라벨의 단맛은
  "단맛 노트가 있다"에 가깝고 패널 강도는 절대 강도다. 오픈판은 순위까지 뒤집힌다(−0.23): 특징 모델이 "블렌드·강배전·
  초콜릿 노트 = 단맛 높음"(로스터리 게이지 관행, [ADR 0011](0011-roaster-gauges-feature-model.md))을 배웠는데 이 패널은
  그런 원두의 단맛을 낮게 줬다. 오픈판 단맛은 로스터리 표기 관행을 재현할 뿐 외부 패널 강도와는 맞지 않는다는 한계로 기록한다.
- 바디는 패널 값이 2.5~3.5에 몰려(상수 3이 MAE 0.36) 변별 신호가 거의 없다 — 이 셋으로는 바디를 평가할 수 없다.
- 부수 발견: 규칙 파서(`parse_bean_text`)는 "dark chocolate" 같은 노트를 다크 로스트로 읽는다(196개 중 65개가 roast=dark로 파싱 — 로스팅 표기 없음 37 · 미디엄 28).
  카탈로그 정규화의 `_roast_from_text`처럼 로스팅 문맥 문장만 보게 고치는 것은 후속 과제로 남긴다(분석 화면 동작이 바뀜).

## 재현

```bash
uv run python -m pipeline run --only collect --source ediya
uv run python -m pipeline run --only normalize --only load
uv run python scripts/derive_brand_beans.py --before <(git show bd0a6f6^:data/curated/brands.yaml)
uv run python scripts/derive_brand_beans.py --variant open
uv run python scripts/eval_zenodo_panel.py   # 외부 패널 검증(xlsx는 data/raw/에 자동 다운로드, 임베딩 캐시)
```
