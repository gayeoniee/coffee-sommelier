# ADR 0012 — 프랜차이즈 원두 값을 공식 설명에서 끌어낸다

- 상태: 채택 (2026-09-28)
- 범위: 전체판(포트폴리오). 오픈판은 같은 `brands.yaml`을 쓰지만 학습 모델은 전체판 것으로만 값을 만들었다(아래 "한계").

## 맥락

프랜차이즈 카드(메뉴 실측 7개 브랜드 + 원두 카드만 있는 3개)의 산미·바디·단맛·향미는 `data/curated/brands.yaml`의
`bean`/`decaf_bean`에서 온다. 지금까지 이 값 20개(10개 브랜드 × 하우스/디카페인)는 전부 손 추정이었다 — 뉴스 기사
("[뉴스]")나 메모에서 "산미 낮은 편, 견과·다크초콜릿" 같은 문구를 보고 1~5를 골랐다. 추천 점수의 절반 가까이가 이
값에서 나오는데, 근거가 공식 자료가 아니고 카드에도 근거가 안 보였다.

## 결정

1. **공식 설명을 사실로만 모은다** — `data/curated/brand_beans_official.yaml`. `pipeline.http.PoliteClient`(robots.txt
   준수, 호스트당 지연)로 각 브랜드 공식 사이트를 읽고, 매장 음료에 쓰인다고 공식 문구가 말하는 원두(하우스·디카페인)의
   이름, 로스팅, 산지·블렌드 구성, 맛 설명을 **원문 그대로** 옮겼다. 브랜드마다 `source_url`과 `verified_at`이 붙는다.
2. **값은 세 가지 출처 중 하나로 정하고 값마다 적는다** — `label_source`:
   - `official_gauge`: 브랜드가 1~5 게이지를 게시하면 그대로(이번 10개 브랜드 중에는 없었다).
   - `official_notes_model`: 공식 맛 설명을 **처음 보는 원두와 똑같은 경로**에 넣는다 — 카탈로그 원두와 같은 형식의
     태그 프리 쿼리 텍스트(`pipeline.embed.embedding_text(..., include_tags=False)`, 이름·로스팅·공식 문구)를 임베딩해
     전체판 학습 모델(`app/core/attrmodel.py`, `app/core/tagmodel.py`)로 예측하고, 공식 문구에 산미·바디·단맛이
     직접 쓰여 있으면(`app/core/textcues.py`, "묵직한 바디" → 바디 4.5, "상큼한" → 산미 4.5) 그 값이 모델보다
     우선한다(`with_text_cues`와 같은 규칙). 게스트에게 "산미 3.5"로 보이므로 0.5 단위로 반올림.
     향미 태그는 **브랜드가 직접 쓴 향미 단어를 우선**한다(규칙 매퍼와 같은 한국어 어휘로 "시나몬·브라운슈가·
     다크초콜릿" → cinnamon/brown sugar/dark chocolate). 공식 문구에 향미 단어가 하나도 없을 때만 태그 모델의 확률
     0.5 이상 태그를 쓴다(SCA 상위 노드 "sweet aromatics" 같은 두루뭉술한 태그와 신맛/쓴맛 같은 기본 맛은 제외).
   - `estimate`: 공식 맛 설명이 없으면(봇 차단·메뉴에 원두 문구 없음·로스팅/공정만 공개) 기존 손 추정을 그대로 둔다.
3. **카드 근거에 공식 문구 한 줄을 보여준다.** `brands.yaml`의 `official_note` → `Item.bean_note`(`app/repo.py`
   `_menu_item`, 실제로 쓰인 원두 — 디카페인 주문이면 디카페인 원두의 문구) → 카드 `evidence`(`app/core/explain.py`
   `card`) 와 설명 LLM 페이로드의 `"원두 공식 설명"`(값이 있을 때만 넣어 기존 설명 평가 24건의 페이로드는 그대로).
   영어 단어가 섞이면 설명 규칙 검사(`foreign_words`)에 걸리므로 카드 문구는 한국어 원문만 발췌했다.

변환 스크립트는 `scripts/derive_brand_beans.py`, 결과(전/후, 쿼리 텍스트, 모델 원출력, 문구 단서, 출처)는
`data/eval/brand_beans_derived.json`. `brands.yaml`은 주석·브랜드 메모를 지키려고 그 결과를 보고 손으로 옮겼고,
`tests/test_normalize_menus.py`가 두 파일이 값·출처 모두 일치하는지 검사한다.

- 페르소나 4명 × 10개 브랜드의 MMR 상위 3개(`app.core.scoring.mmr_top_k`, 조건 통과 후): 서로 다른 메뉴 이름 수가
  **27 / 24 / 27 / 24로 전후 동일** — 붕괴 없음. 브랜드별 1위 점수의 퍼짐(최대−최소)은 디카페인+산미 26 → 28,
  저카페인+우유X 30 → 33, 제한없음 25 → 21, 디카페인+단맛 28 → 33. 값이 모두 비슷한 쪽으로 몰리지 않았다.
  예: 저카페인+우유X(산미 2 선호) 손님에게 폴바셋 1위 점수는 84 → 68(산미 4.5가 된 탓), 디카페인+단맛 손님에게 커피빈은
  68 → 95(디카페인 원두의 "달콤" 문구).

## 한계 / 결정하지 않은 것

- **문구 단서는 강도를 모른다.** `textcues`는 "은은한 단맛"도 "단맛"으로 보고 4.0을 준다(할리스 디카페인), "부드러운
  산미"는 "산미 약"으로 보고 1.5를 준다(할리스 하우스). 분석 화면(`analyze_bean`)과 같은 규칙을 일부러 그대로 썼다 —
  브랜드 카드만 다른 규칙을 쓰면 같은 문구가 화면마다 다른 값이 된다. 강도 부사 처리는 textcues 쪽 개선 과제로 남긴다.
- **마케팅 문구는 학습 분포 밖이다.** 모델은 coffeereview 리뷰(영어)·국내 로스터리 노트로 학습됐다. 산미·단맛처럼
  공식 문구가 말하지 않는 값은 모델이 사실상 사전값에 가깝게 답한다(메가 산미 2.44 등). 그래서 향미 태그는 모델보다
  공식 단어를 우선했고, 공식 단어가 없을 때 모델 태그(메가 디카페인 "woody" 0.85 등)는 출처가 `official_notes_model`
  로 남는다.
- **오픈판**: 같은 `brands.yaml`을 쓰므로 오픈판 카드도 이 값을 쓴다. 값 자체는 공식 페이지 사실 + 규칙/모델 출력이며
  리뷰 원문을 담지 않는다. 다만 모델은 전체판(coffeereview 포함 학습)이다 — 오픈판에서 이 값을 쓰는 게 라이선스상
  문제인지는 공모전 문서 쪽(ADR 0011 담당)에서 판단할 일로 남긴다.
- 공식 게이지가 생기면(`gauges`) 스크립트가 그 값을 먼저 쓴다. 투썸(봇 차단)·컴포즈(설명 없음)는 브랜드가 공개하기
  전까지 추정이다.
